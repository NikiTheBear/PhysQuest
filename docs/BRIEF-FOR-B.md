## 2. 接口契约（唯一需要记住的东西）

```ts
interface LabStageProps {
  params: LensParams;      // 当前参数，唯一状态源在网页层
  stage: Stage;            // 'primary' | 'junior' | 'senior' | 'university'
  metrics: LensMetrics;    // 引擎算好的结果，直接用
  showRays: boolean;       // 显示三条特殊光线
  showVirtualExtensions: boolean;  // 显示虚像虚线
  highlightIds?: string[]; // 需要高亮的器材（AI 演示用）
  narration?: string | null;       // AI 演示气泡文字
  demoMode?: boolean;              // 演示播放中（关掉自动过渡）
}
```

`params` 和 `metrics` 的完整定义在 `src/core/contracts.ts`，看一眼就懂。

**你只读这两个。** 不要自己调 `solve()` 重算一遍（会不一致），不要存 state（状态只能有一个源头）。

### ⚠️ 一个必须知道的坑：y 轴是反的

物理里 **y 向上为正**，SVG 里 **y 向下为正**。

引擎给出来的一切（`imageY`、`traceRays()` 的每个点）都是**物理坐标**。
画之前必须取反，否则像会跑到轴上边去。

参考实现里所有转换都走这一个函数，照抄就行：

```ts
/** 物理坐标 y（向上为正）→ SVG y（向下为正） */
const Y = (y: number) => -y;
```

这个坑我第一次写的时候踩了，浪费了半小时。

## 3. 你的七个任务

按顺序做，每个都有验收标准。做完一个发我，我合并、自动部署、你们都能看到网址更新。

### B-1 · 光具座静态图

| | |
|---|---|
| **做什么** | 底座 + 刻度尺 + 蜡烛 + 透镜 + 光屏，比例与 `params` 一致 |
| **验收** | 改 `u` 数字，蜡烛位置跟着变；浏览器缩放到 200% 不模糊（用 SVG，不用 canvas） |
| **参考版状态** | ✅ 已完成，可以改进美观度 |

### B-2 · 三条特殊光线

| | |
|---|---|
| **做什么** | 黄：平行光轴→过 F′；青：过光心不偏；粉：过前焦点→出射平行 |
| **验收** | 任意物距下，光线出射方向与几何作图一致（误差 < 1px）；u < f 时画出虚线延长线 |
| **参考版状态** | ✅ 已完成，用了引擎的 `traceRays()` |

**注意**：`u < f` 时第三条光线（过前焦点那条）实际上打不到透镜，参考实现里不画它。这是教学惯例，不是 bug。

### B-3 · 光斑模糊 ⭐

| | |
|---|---|
| **做什么** | 光屏不在像的位置时，屏上显示的是一团**模糊光斑**，不是一个点 |
| **验收** | ① 偏离越大光斑越大（单调）② `screenX === v` 时恰好为 0 ③ `u < f` 时没有光斑 |
| **参考版状态** | 🟡 用 SVG `feGaussianBlur` 做了初版，可以更好 |

**这一条是整个实验台的灵魂。** 几乎所有在线模拟器都偷懒，直接"没像"了事。但学生手动挪光屏找清晰点的整个过程，全靠这个模糊圈。做对了，这个实验才有"手感"。

引擎已经给了 `metrics.blurDiameter`（单位 cm），你只管把它画出来。

### B-4 · 三个反直觉现象的画面 ⭐⭐

| 现象 | 学生 100% 猜错的地方 | 必须画成什么样 |
|---|---|---|
| **遮住透镜上半** | 以为像会只剩一半 | 像**完整、位置不变、大小不变**，只是整体变暗（`relativeIlluminance ≈ 0.5`） |
| **u = f** | 以为会成一个巨大的像 | 出射光线**互相平行**，视觉上不交于一点，屏上什么都没有 |
| **u < f** | 以为光屏上能接住 | 屏上**永远没有像**，虚线画出透镜左侧的虚像，比物大、正立 |

**B-4 是整个项目里最值钱的一件事。** 这三个现象做对了，凸透镜这个实验就成了。

## 5. 技术约束

| 项 | 规定 |
|---|---|
| 渲染技术 | **SVG**（不是 canvas）。理由：任意缩放不模糊、可被无障碍读取、能用 CSS 高亮 |
| 坐标系 | 全程厘米。viewBox 直接就是厘米，不做刻度变换 |
| 目标尺寸 | 最小 1280px 宽，**不做手机适配**（PLAN §0 已定） |
| 帧率 | 拖滑块时 60fps。如果卡，说明你在 render 里做了重活，用 `useMemo` |
| 第三方库 | **不要引入**。图表、动画手写就够，多一个库多一份风险 |
| 文件范围 | 只改 `labs/optics-lens/LabStage.tsx`、`labs/optics-lens/rig/**`、`ai/demo/**` |

## 6. 怎么验证你画对了

引擎有 12 条测试，你的图必须和它们一致。最常用的几组对照：

| 参数 | 应该看到 |
|---|---|
| u=30, f=10, screenX=15 | 倒立缩小的像，光屏上清晰，弥散圆 0 |
| u=20, f=10, screenX=20 | 倒立等大的像（和物一样大） |
| u=15, f=10, screenX=30 | 倒立放大的像（2 倍） |
| u=10, f=10 | 三条光线出射后互相平行，屏上什么都没有 |
| u=6, f=10 | 透镜左侧（负 x 侧）有一个正立、放大的虚像，屏上没像 |
| u=30, f=10, maskTop=true | 像的位置大小完全不变，只是变暗 |

**跑测试**：`cd apps/web && npm test`

跑完看到 `12 passed`，就说明引擎是对的。你的图对不上这 12 组，就是图画错了，不是引擎错。

## 8. 参考实现里我踩过的两个坑（省你时间）

**坑 1：y 轴反的。**
物理向上为正，SVG 向下为正。像会画到轴上边去。解法见 §2。

**坑 2：纵向拉伸会裁切。**
光具座本身又长又扁（63 cm 宽、5 cm 高），照实画就是一条线。我试过纵向放大，结果 `viewBox` 变了但元素坐标没跟着变，画面被裁掉一大块。

**现在的做法**：老老实实按厘米画，纵向靠 `halfH` 留白撑出一个好看的宽高比，不去拉伸坐标。学生量得出来，图也好看。
