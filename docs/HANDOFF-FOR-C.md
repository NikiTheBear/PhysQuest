## 1. 三个字段要写什么（最重要的一节）

### `analogy` —— 生活类比

**一句话：找一个学生在生活里真的见过的东西。**

| ❌ 不合格 | ✅ 合格 |
|---|---|
| 凸透镜是一种会聚透镜。 | 正午把放大镜对准太阳，最亮的那个点就是焦点——这是你唯一能用尺子量出来的镜头参数。 |
| 虚像不能成在光屏上。 | 像镜子里的你——你伸手过去，那边什么也没有。 |
| 物近像远。 | 像和物像翘翘板的两头：你把它那头压近焦点，它这头就翘得又高又远。 |

**要求**：

- 举的东西必须是初中生见过的（手机、放大镜、眼镜、投影仪、照相机、镜子、水里的筷子、彩虹）
- 不要用"就像……一样"这种空比喻，要有具体的画面
- 长度：**20–60 字**。写短了没画面，写长了学生不看

### `why` —— 为什么

**一句话：不是"是什么"，是"为什么会这样"。**

这是整个项目最要紧的一个字段。光伏那个原型之所以"知识学习不够"，就是因为它的卡片只写了"是什么"，学生只能背。

| ❌ 不合格 | ✅ 合格 |
|---|---|
| 因为物距变大时像距会变小。 | 公式 1/f = 1/u + 1/v 里，u 变大，1/u 就变小，1/v 就得变大才能凑够 1/f——所以 v 变小。不是"记规律"，是算术。 |
| 虚像是假的像。 | 折射后的光线仍然是发散的，它们不会在透镜后面相交，只有反向延长才交于一点——所以叫虚像。 |

**要求**：

- 必须解释**机制**，不能只重复结论
- 允许用公式，但要用中文说清楚公式在讲什么
- 长度：**40–120 字**
- **绝对不要**写"记住这个规律就行"这类话

## 2. 每一栏的意思（对照着填）

```json
{
  "id": "K-O2-09",                      ← 别改。这是身份编号，全项目都靠它互相指认
  "stage": "junior",                     ← 别改
  "title": "物距小于焦距：正立放大的虚像",   ← 别改
  "oneLine": "物体进到一倍焦距以内，光屏上找不到像……",  ← 可以微调，但要一句话
  "analogy": "拿放大镜看字，字变大，但你没法把它「投」到纸上去。",  ← ★ 你主要改这个
  "formula": "",                          ← 有公式就填，没有留空
  "why": "折射后的光线仍然是发散的……",      ← ★ 你主要改这个
  "misconceptions": ["MIS-O2-01", "MIS-O2-03"],  ← 别改（改了要告诉我）
  "prerequisites": ["K-O2-03", "K-O2-04"],       ← 别改
  "labPreset": { "u": 6, "f": 10, "screenX": 30 }, ← 别改
  "difficulty": "beginner"                ← 别改
}
```

**带 ★ 的两个字段是你的地盘。** 其他字段别动，动了系统会报错。

## 3. 题库怎么写

```json
{
  "id": "Q-O2-001",                 ← 按顺序往后编：Q-O2-016、017……
  "type": "single_choice",          ← 或 "short_answer"
  "question": "某凸透镜焦距 f = 10 cm，把蜡烛放在距透镜 30 cm 处。光屏上成的像是什么样子？",
  "options": ["倒立、缩小的实像", "倒立、放大的实像", "正立、放大的虚像"],
  "answerIndex": 0,                 ← 正确答案是第几个（从 0 数）
  "knowledgeId": "K-O2-05",         ← 这题考哪个知识点（必须存在于 knowledge.json）
  "misconceptionId": "MIS-O2-05",   ← 这题打哪个误区（必须存在于 misconceptions.json）
  "explanation": "u = 30 cm > 2f = 20 cm，属于「物距大于二倍焦距」，成倒立缩小的实像。相机就是这个原理。"
}
```

**出题的三条硬要求**：

1. **每道题都要挂一个 `misconceptionId`。** 这是错题本的基础——学生答错，系统才能推对应的知识卡。
2. **选项必须是"看起来很合理"的错误**，不能是明显凑数的。三个选项都要有学生真的会选。
3. **`explanation` 要说清"为什么其他选项不对"**，不能只说正确答案。

**简答题**（`type: "short_answer"`）没有 options，改成 `answerKey`，写评分要点。

## 4. 怎么检查

在项目根目录跑：

```bash
node shared/knowledge-data/schema/validate.mjs
```

它会告诉你四类问题：

| 输出 | 意思 | 怎么办 |
|---|---|---|
| `✗ 缺字段 why` | 必填字段空了 | 补上 |
| `✗ 引用了不存在的误区 MIS-O2-4` | 编号打错了（少写一个 0） | 改成 `MIS-O2-04` |
| `✗ 前置 K-O2-99 不存在` | 指向了没编号的知识点 | 改对，或者问我要不要新建 |
| `⚠ why 字段太短（少于 12 字）` | 提醒，不是错误 | 建议写长点 |

**全部通过的时候会看到绿色 `✓ 全部通过`。**

写错了不要怕——这个脚本就是给这个用的，它不会改你的文件，只报告。

## 5. 老师使用手册怎么写（`docs/handbook/`）

这是**你独有的优势区**。你本来就是新手，你摸索的每一步，就是真实老师会卡住的地方。

建议结构：

```
docs/handbook/
├── 01-五分钟上手.md      第一次打开，从哪点起
├── 02-一节课怎么安排.md   45 分钟怎么分配（这个最实用）
├── 03-常见问题.md         打不开、光屏上没像、没法提交……
└── 04-接AI（可选）.md     想用 AI 功能怎么配
```

**写的时候记住一件事**：你踩的每个坑都要写进去。你觉得"这还用说吗"的地方，恰恰是别人会卡住的地方。

每写一条，问自己：**一个从没用过这东西的老师，看得懂这句话吗？**
