# 本地启动器 · 使用说明

> 这个文件夹里的小程序，解决一个很具体的问题：**浏览器不让网页直接调大模型接口。**

---

## 为什么需要它

你在网页里填了 API Key，点"测试连接"，结果看到：

```
Failed to fetch
```

英文的意思是"请求没能发出去"。真实原因有两个，但浏览器不会告诉你：

1. **跨域限制（CORS）** —— 大部分 AI 厂商（尤其国内的）不允许网页直接调它们的接口。这是浏览器的安全规矩，不是厂商的问题，也不是你配错了。
2. 网络不通 / 端点地址写错。

本地启动器解决第 1 个：它在**你自己电脑上**起一个小服务，网页把请求发给它，它再转发给厂商。因为转发发生在"同一条网线里"，浏览器就不拦了。

---

## 它不改变那条安全红线

这个项目的红线是：**我们的服务器永远不碰学生的 Key**。

启动器**不是我们的服务器**。它是跑在你自己电脑上的一个进程：

| | 我们的服务器（不存在） | 本地启动器 |
|---|---|---|
| 在哪 | 互联网上某台机器 | **你自己的电脑** |
| 谁能访问 | 所有人 | **只有这台机器**（只监听 `127.0.0.1`） |
| Key 经过它吗 | 会 | 会，但**只在内存里过一下，不写日志、不落盘** |

一句话：它是你电脑上的一个"传话的"，不是我们中间的一个"收信的"。

---

## 怎么用（三步）

### 第一步：确认装了 Node.js

打开终端（macOS 按 `Cmd + 空格`，输入 `Terminal`），粘贴：

```bash
node --version
```

看到 `v18` 或更高的版本号就跳过这步。

没有的话去 **https://nodejs.org** 下载 LTS 版本，一路"下一步"就行。

> **为什么用 Node 而不是 Bun？**
> 早期版本用的是 Bun，但 Bun 的安装包在国内下载经常很慢（有时要十几分钟）。
> Node.js 是绝大多数电脑上本来就有、或者官网直连能秒下的东西，所以换掉了。
> 现在这个启动器**零依赖**，不需要 `npm install`，不需要任何第三方包。

### 第二步：双击启动器

| 系统 | 双击哪个文件 |
|---|---|
| macOS | `start.command` |
| Windows | `start.bat` |

第一次双击如果提示"无法打开，因为它来自身份不明的开发者"：

- macOS：右键点 `start.command` → 选「打开」→ 再点一次「打开」
- 或者去「系统设置 → 隐私与安全性」，下面会有一条提示，点「仍要打开」

启动后你会看到一个终端窗口：

```
  🔭 探理实验室 · 本地启动器
  ─────────────────────────────────────────
  ✓ 服务已启动：http://127.0.0.1:8787
  · 只监听本机 127.0.0.1，局域网里其他设备访问不到
  · 配置文件：未找到（可在网页里填 Key）
```

**这个窗口不要关。** 关掉就等于停止服务。

浏览器会自动打开。如果没有，手动访问 `http://127.0.0.1:8787`。

### 第三步：在网页里填 Key

1. 右下角点 ✦ 打开 AI 助教
2. 点 `⚙` 打开设置
3. 连接方式选「**本地启动器（推荐）**」
4. 选一个厂商（或填自定义端点）
5. 填 API Key
6. 点「测试连接」

看到绿色 `✓ 连上了` 就成了。

## 两种配 Key 的方式

### 方式 A：在网页里填（推荐个人用）

点 ⚙，填一次，存在浏览器里。换电脑要重填。

### 方式 B：写进配置文件（推荐学校批量配）

复制 `config.example.json` 成 `config.local.json`，填上：

```json
{
  "endpoint": "https://api.deepseek.com/v1/chat/completions",
  "model": "deepseek-chat",
  "apiKey": "sk-你的key",
  "timeoutMs": 60000
}
```

填完之后：
- 启动器启动时自动读进来
- 网页里那个 Key 框**可以留空**
- 设置面板会显示「启动器已经读到 config.local.json 里的 Key」

> ⚠️ **`config.local.json` 不要提交到 Git。** 已经在 `.gitignore` 里了。
> ⚠️ **如果要把整个文件夹拷给别的老师/学校**，先把这个文件删掉，否则你的 Key 跟着走了。

## 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击没反应 | macOS 拦截了 | 右键 → 打开 |
| `找不到 Node.js` | 没装 | 去 nodejs.org 装 LTS 版本 |
| 端口 8787 被占用 | 开了两个启动器 | 关掉一个，或 `PORT=8788 node src/server.mjs` |
| 网页打不开 | 启动器窗口关了 | 重新双击启动器 |
| 设置里显示「启动器没在跑」 | 同上 | 同上，点「重新检查」 |
| 测试连接报 `401` | Key 错了 | 去厂商控制台重新复制 |
| 测试连接报 `402/429` | 没钱了或太频繁 | 充值 / 等一分钟 |
| 测试连接报「端点地址写错了」 | 多写了路径 | 只填到 `/v1`，不要带 `/chat/completions` |
| 端口 8787 被占用 | 开了两个启动器 | 关掉一个，或改 `PORT` 环境变量 |

## 技术细节（给 B 看）

如果你是接手实验室部分的成员，需要知道：

- 转发端点：`POST /api/llm?target=<编码后的目标URL>`
- 请求头 `Authorization` 原样透传给上游
- 请求体原样透传，**不解析、不改写**
- 响应原样返回（包括上游的错误状态码，前端靠这个翻译成人话）
- 健康检查：`GET /api/health` → `{ ok, version, hasConfig, model }`
- 只接受 `Origin` 为本机（`127.0.0.1` / `localhost` / `file://`）的请求

**不要**在这个文件里加任何"上报""统计""云端配置"之类的东西。它必须是纯粹的、本地的、可被任何人审计的。
